# blink-editing — 《眨眼之间》剪辑技能

把沃尔特·默奇《眨眼之间：电影剪辑的奥秘（第2版）》（夏彤 译）的方法论，转成一个可直接调用的 **Claude Agent Skill**。

不是读书笔记，是可执行的判断结构：六原则权重、剪接点定位、分叉点枚举、试映诊断、数字剪辑防错。

## 这个技能能干什么

- 判断某个剪点对不对、该往哪边挪
- 审片时定位"观众看不进去/结构不匀"的真实病根
- 与导演/制片人做结构沟通（诱饵沟通法）
- 评估素材量、工期、人手（35 万英尺阈值）
- 设计试映与反馈回路
- 数字剪辑流程决策（采集清晰度、套对、版本节制）

## 目录结构

```

```

章节文件按需加载，不占常驻上下文。

## 安装

```bash
# 全局（Claude Code / Pi 运行时）
git clone https://github.com/10000-coder/blink-editing-skill.git ~/.claude/skills/blink-editing
# 或 ~/.agents/skills/blink-editing
```

装好后用 `/blink-editing` 调用，或带参数：`/blink-editing ch14`、`/blink-editing 六原则`、`/blink-editing 试映`。

## 用法示例

- 「这场对话该怎么切？」→ 走 ch14 分叉点 + 眨眼定位
- 「观众说结尾赶」→ 走 ch12 反射性疼痛，回到 5 分钟前找说明缺口
- 「为了不越轴牺牲了表演，可以吗？」→ 六原则：把 4% 放在 51% 之上
- 「素材 80 小时，只有我一个剪辑师」→ ch09 阈值与分工

## 核心权重（书中的骨架）

情感 51% ＞ 故事 23% ＞ 节奏 10% ＞ 视线 7% ＞ 二维平面 5% ＞ 三维连贯 4%。
冲突时只能向下牺牲；高层达标会掩盖低层瑕疵，反之不成立。
